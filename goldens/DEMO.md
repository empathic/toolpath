# Capturing goldens: `path goldens`
Capture is a tool, not a script: hermetic (empty env, temp HOME/XDG/store dirs, cwd `/`), to every target, with a pinned manifest. `scripts/goldens.sh <args>` = `cargo run -p path-cli -- goldens <args>`; the test calls the same library. The rules are in [`docs/GOLDENS.md`](../docs/GOLDENS.md) (13 rules plus this repo's appendix); `check` prints its sha256 and fails without it.
1. `path goldens init`: captures the repo fixtures (codex, claude, copilot, pi, claude-compacted) to every other format; one `captured <src> -> <dst> (raw bytes|canonical, N bytes)` line each. One fixture: `path goldens capture <harness> <fixture> [--name N] [--project P]`.
2. `path goldens check [name]`: re-runs; prints `ok <src> -> <dst>` per golden, `ok <set> -> <adapter> -> IR` per round trip, `ok <set> shed` per recomputed shed report, the three known defects `(still present)` and the qualifier review, ends `46 ok, 0 problem(s)`; exit 1 with a path-named line diff, `PIN MOVED <item>`, `newly dropped …`, `round trip gains …`, or a known defect that `looks FIXED` / `CHANGED and is NOT fixed` otherwise. `path goldens diff <name>` shows more diff; `path goldens list` shows sets, agent versions, targets. `check` also runs `qualifier review` (spec rule 11) and FAILS CLOSED: no `qualifier` binary (`$TOOLPATH_GOLDENS_QUALIFIER`, else PATH) is a problem; `--no-qualifier` skips the review on purpose and says so in an `info` row. The dev shell does not ship qualifier, so the cargo goldens test skips it explicitly unless `TOOLPATH_GOLDENS_QUALIFIER` is set.
3. `path goldens capture-live <claude|codex|pi|copilot>` (`capture-claude` = `capture-live claude`): one REAL headless session in a temp HOME, in your own terminal. Credentials only ever go into the temp dir: codex copies `~/.codex/auth.json`+`config.toml`, pi copies `~/.pi/agent/auth.json`, copilot forwards `$COPILOT_GITHUB_TOKEN`/`$GH_TOKEN`/`$GITHUB_TOKEN` (e.g. `export COPILOT_GITHUB_TOKEN=$(gh auth token)`), claude as below; a secret from a credential file (tokens, keys) found in the transcript refuses the capture, but account identifiers (account/user id, email-shaped account fields, from the credential files or the transcript's own `creator_account_id`/`userID` fields) are redacted to `acct-redacted`/`user-redacted`/`email-redacted` and listed under `leak_check.redacted` in the manifest. `cursor`/`opencode` are refused with the reason (cursor-agent's protobuf store and opencode's SQLite are not single adapter-readable files). Optional `--bin`, `--name`, `--model`. Claude: token from `$CLAUDE_CODE_OAUTH_TOKEN`/`$ANTHROPIC_API_KEY` or Keychain `claude-code-oauth-token`, hex-decoded and prefix-routed, never printed or written; run in your own terminal; the model runs bare `ls`, tool scope `Bash(ls)`), leak-checked (refuses real home, token, local username, any address except Claude Code's `noreply@anthropic.com`, which the manifest records as allowed), captured as set `claude-session`; commit `goldens/`. Model output varies per run: capture once; check is deterministic over the committed input.
Regenerate on purpose: fix the code, `path goldens capture --all`, review `git diff goldens/`, commit. Never hand-edit; check refuses a golden that disagrees with its manifest sha.
What `check` compares per set: input sha256 and each output's sha256 + command + form; nothing else can fail a set. The environment the capture ran under (goldens source files, Cargo.lock, flake.lock, rust-toolchain, `path` version, nix `path` binary narHash) and the producer (binary sha, nix store path if any, repo rev) are recorded beside the pins and reported as `info` when they move: a lockfile bump, a doc edit or a squash merge does not change what a golden is, and an environment change that alters an output fails on that output's sha. Drift demo: edit one output sha in `goldens/manifest.json`, `path goldens check <set>` prints `PIN MOVED`; `git checkout goldens/manifest.json`.
Each set's `harness` records the AGENT that wrote the input. Fixtures of unknown origin get the version the input declares (else `unknown`) plus the commit that first added them; a live capture gets the binary path, `--version` and sha256. A changed local agent is `info`, never a failure.

Known defects (`goldens/known-defect/`): codex->claude emits foreign entry types; `export codex -o` writes the caller's cwd; claude -> IR -> claude renames `message.stop_reason` to `message.stopReason`. A fix fails check with `looks FIXED` and a diff: recapture to acknowledge. Any other change fails with `CHANGED and is NOT fixed`.

Regressions check catches, shown (each a throwaway edit, then reverted): dropping `user_type` in `crates/toolpath-claude/src/provider.rs` gives `FAIL claude shed: newly dropped on the same-format round trip (1): userType` (and the same for `claude-session`, plus `IR string_chars … text lost`), where before this gate all output goldens still matched. Projecting `stop_reason: None` in `crates/toolpath-claude/src/project.rs` gives `known defect …claude-roundtrip-renames.tsv CHANGED and is NOT fixed (message.stop_reason is no longer written under either name)`, where it used to say the defect may be FIXED.
Findings: `export copilot` is nondeterministic (random session id, key order), so capture's two-run probe stores canonical form; the claude adapter needs the file named `<sessionId>.jsonl`. Needs `nix` for the wrapper; the nix pin is verified only where its store path exists; repo rev and rustc are recorded, not pinned.

## What the IR keeps on purpose, and what is shed (`path goldens shed`, `roundtrip`; numbers from goldens/shed/*.json, which `check` recomputes)
The IR keeps what a reader of the conversation needs: roles and actors, text, tool calls with their ids and inputs, the step DAG (parents), timestamps, per-message token totals, and, for same-harness replay, the raw entry under `structural.entry_extra`. That last part is why claude -> IR -> claude is a fixed point (IR byte-identical after key sorting): the claude projection replays the extras, no other projection does, so a claude session through codex, pi or copilot loses 212-217 key paths (claude-session) while text and tool uses survive.
Shed by design (telemetry and plumbing, no analogue elsewhere): usage detail (`cache_creation.*`, `iterations[]`, `thinking_tokens`, `server_tool_use`, `service_tier`, `speed`, `inference_geo`), request plumbing (`requestId`, `promptId`, `promptSource`, `turnOrigin`, `turnPosition`, `apiBlockIndex`, `permissionMode`), null-valued fields, and whole event types with no counterpart (attachment, last-prompt, atis-latch, queue-operation, cost-state do not exist in codex).
Shed as DEFECTS (recorded, not yet fixed): the envelope fields `version`, `userType`, `entrypoint` (present on 20 of 29 source records, on 12 after the round trip; measured, the hand-run figure of 17 did not reproduce); the thinking-block `signature`; and the rename `message.stop_reason` -> `message.stopReason` (the docs say `stopReason` is a different, hook-provided envelope field, so the projection writes the API field under the wrong name). Also: codex -> claude emits 34 of 44 lines as codex event types (known defect), and codex -> copilot -> IR keeps 3,077 of 13,445 text characters.
